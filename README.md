# ToKaWalk

An offline-first voice AI companion for Android walkers, with intelligent model routing,
production observability, and a QLoRA fine-tuned on-device model.

**Live demo:** https://to-ka-walk.vercel.app
**API:** https://tokawalk-api.onrender.com
**On-device model:** https://huggingface.co/swapnilbehere/tokawalk-qwen-1.5b *(after fine-tune)*

---

## System Architecture

```
Voice Input (STT)
      ↓
ConversationEngine          ← state machine: idle→listening→processing→speaking
      ↓
 local / online?
      ↓                           ↓
On-device LLM            BackendLLMService → Railway API
(Qwen 2.5 1.5B,                   ↓
 fine-tuned QLoRA)         QueryClassifier
                           (complexity + network latency)
                                   ↓
                           Groq API (llama-3.1-8b-instant)
                                   ↓
                           Structured Logger
                           (model, latency, routing_reason, session_id)
                                   ↓
                           SQLite (Railway)
                                   ↓
                           Weekly Eval Batch
                           (LLM-as-judge: conciseness / helpfulness / safety)
```

---

## Key Engineering Decisions

**Offline-first architecture:** The app runs Qwen 2.5 1.5B (Q4_K_M, ~1.8GB) entirely
on-device via llama.rn. No network required. Online mode routes through a FastAPI backend
on Railway — users switch modes mid-session, the engine handles the transition cleanly.

**Model routing:** `QueryClassifier` in the backend routes each request based on query
complexity (keyword heuristics) and real-time network latency measured before each call.
Simple queries and poor-network conditions route to local; factual and complex queries use
Groq. All routing decisions are logged with reasons and visible in `/api/stats`.

**Resilient voice pipeline:** STT classifies 3 failure modes (no_match, network_error,
unavailable) with different restart delays. LLM errors classified into auth / rate-limit /
network with appropriate retry strategies. Automatic offline degradation with no
user-facing error.

**Eval pipeline:** Weekly batch samples 50 unscored production turns, scores each on
conciseness / helpfulness / safety (1–5) using LLM-as-judge, stores results in SQLite.
Avg eval score visible at `/api/stats`.

**QLoRA fine-tuning:** Qwen 2.5 1.5B fine-tuned on ~200 walking-companion conversations
(50 high-scoring production turns + 4× synthetic variations generated by Groq).
Evaluated before/after on conciseness score with held-out prompts.

## Mobile Setup

```bash
git clone https://github.com/swapnilbehere/ToKaWalk.git
cd ToKaWalk
npm install
npx react-native run-android --device <device-id>
```

On first launch the app downloads the LLM model (~1.8 GB). Requires Wi-Fi for initial
setup. Say **"Bye Nova"** to end a walk session.

## Backend Setup (local dev)

```bash
cd api
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # add GROQ_API_KEY
uvicorn main:app --reload
```

## Running the Eval Pipeline

```bash
cd api
# Score 50 unscored production turns
DB_PATH=/path/to/tokawalk.db python -m eval.run_eval --n 50
```

## Fine-Tuning (Google Colab)

```bash
# 1. Generate training data (needs scored production turns)
cd finetune
DB_PATH=../api/tokawalk.db python generate_data.py

# 2. Upload training_data.jsonl to Colab, then run:
pip install -r requirements.txt
python train.py

# 3. Push to HuggingFace Hub
huggingface-cli upload swapnilbehere/tokawalk-qwen-1.5b ./tokawalk-qwen-1.5b
```
